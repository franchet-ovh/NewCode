Focus Editor for Apple Silicon (macOS 11 or newer)

Drag Focus Editor.app to Applications, then open it from Applications.
The editor opens a native desktop window by default; --ui selects it explicitly.
Use --browser for a dedicated Chromium or Google Chrome window (WebGL 2 required),
with a temporary private profile and the renderer sandbox enabled.
No Node.js or Electron is needed.
Closing the window warns about unsaved documents, stops the backend, and removes
the temporary profile. Reloads and connection loss retain the session
while the window is alive. External links open in the normal system browser.
Addons are distributed separately. Open Addons below Source Control to install
local addon.toml or addon .tar.gz packages and manage updates, enablement,
credentials, and uninstall. Installed addons live beside logs under
~/Library/Application Support/focus-editor/addons. Updates preserve workspace data
and OS-keyring credentials. Automatic addon releases currently provide Linux
packages only; build macOS addons from source. The manager checks supported
editor versions, protocol, and platform before installation.
This download has an ad-hoc signature, not an Apple Developer ID signature,
and is not notarized. macOS may block the first launch. After attempting to
open it, use System Settings > Privacy & Security > Open Anyway if offered.
Do not disable Gatekeeper globally.

Git, Docker, Codex, and OpenCode are separate optional installations.
Configure provider authentication with each assistant's CLI before enabling it.
Finder launches also search ~/.local/bin, ~/.opencode/bin, /opt/homebrew/bin,
and /usr/local/bin after the inherited PATH.

For terminal diagnostics or to open a workspace directly:
  /Applications/Focus\ Editor.app/Contents/MacOS/focus-editor ~/projects/my-project
  /Applications/Focus\ Editor.app/Contents/MacOS/focus-editor --browser ~/projects/my-project
The macOS application stays attached when launched from a terminal.
App mode prints a private session URL there for diagnostics. If Chromium cannot
start, inspect the error or use --ui; the launcher never retries unsandboxed.
Browser-reserved shortcuts can take precedence; use editor menus or --ui.
Use --version to display the version, or --help to list editor options without
opening a window. focus-editor-server --help lists server options without starting it.
See the project README for features and troubleshooting.

Shared remote server (or use /Applications/Focus\ Editor.app/Contents/MacOS/focus-editor-server):
  focus-editor-server
  focus-editor-server --bind 0.0.0.0 --port 8999
  focus-editor-server --config /path/to/server.toml

Install focus-editor-server beside focus-editor. The server stays in the foreground,
requires no browser or display, and defaults to 0.0.0.0:8999. Configure its HTTP Basic
Auth login in focus-editor/server.toml in the user configuration directory
(Linux: ~/.config; macOS: ~/Library/Application Support):
  bind = "0.0.0.0"
  port = 8999
  username = "your-login"
  password = "your-password"
Use chmod 600 on this file. FOCUS_EDITOR_SERVER_USERNAME/PASSWORD override file
credentials; CLI bind/port override file values. The old focus-editor --server
flag directs you to the separate binary.

Open http://HOST-IP:8999. App and --ui editors automatically register, including
when the server starts after them or restarts. The Workspaces list remembers
previously opened folders; Add workspace accepts a host folder path. Start opens
a stopped workspace in a browser-only session; Open selects an existing session.
Click Take control to edit; other viewers remain connected. Closing the browser
or stopping the server leaves all sessions running. Restart the server to reattach
to the same unsaved buffers, terminals, and addons. Stop ends a browser-only session
with save/discard/cancel choices for dirty documents. Close local editors from
their own windows. See README.md for configuration and troubleshooting details.
